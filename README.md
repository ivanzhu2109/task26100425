# GigNexus 人才匹配库

Go 实现的内存人才匹配库，由上层直接调用，无接口层。提供两种能力：

- `Store.Load`：加载候选人静态资料快照（加载后资料不变，可并发查询）。
- `Store.Match`：按四项权重对全部候选人完整评分，返回前 20 名匹配结果。

## 用法

```go
s := &matcher.Store{}
if err := s.Load(candidates); err != nil { /* 非法快照 */ }
matches, err := s.Match(matcher.Query{
    Skills:    []uint16{101, 205, 308},   // 所需技能集合，非空
    Hours:     40,                        // 预计工时，正整数
    BudgetMin: 200_000,                   // 预算下限，美分
    BudgetMax: 400_000,                   // 预算上限，美分
    Weights:   matcher.DefaultWeights(),  // 技能40/价格25/口碑25/状态10
    MinScore:  0,                         // 最低最终分
})
// matches 按最终分降序、同分按编号升序，最多 20 条，含最终分。
```

## 评分规则

- 技能分：命中的所需技能数 / 所需技能总数 × 10000，向下取整；多出技能不扣分，零重合不淘汰。
- 价格分：预计金额（时薪 × 工时）在预算闭区间内比例为 1；低于下限为金额/下限，高于上限为上限/金额；× 10000 向下取整。
- 口碑分：星级总和 / (条数 × 5) × 10000 向下取整；无评价为 0。
- 状态分：可接单 10000、忙碌 5000、休假 0。
- 最终分：四项整数分 × 对应权重求和（0 至 1,000,000，不再舍入）；权重为非负整数且合计 100，允许单项为 0。
- 返回最终分 ≥ 最低分的前 20 人；最低分恰好等于得分时仍参与排序。

## 实现要点

- 候选人按 SoA 布局存储（编号 / 时薪 / 预计算口碑分 / 预计算状态分 / 定长技能行），全量扫描缓存友好。
- 所需技能转为 8 KiB 位图，命中计数为无分支位测试；技能权重为 0 时整体跳过。
- 价格贡献仅取决于时薪：时薪跨度 ≤ 1M 时按查询预计算查表，否则逐人除法回退，两种路径结果一致。
- 所有候选人都参与评分（包括零技能重合与休假者），不会提前漏掉任何人。

## 测试

```sh
go test ./...
```

正确性测试与独立逐人暴力实现全量对照，覆盖：零技能重合者挤入前 20、
改变权重后榜单翻转、取整造成第 20 名附近多人同分（同分按编号升序）、
最低分恰好等于得分、随机快照与随机查询模糊对照、时薪跨度极大的回退路径、
非法快照与非法查询的校验。

## 性能报告（可复现）

```sh
go test ./matcher/ -run TestFullScalePerformance -v
```

验收规模：500,000 名候选人、10,000 种技能；每人 10 种技能、时薪 10~200 美元、
三种状态各约三分之一、口碑覆盖完整星级范围；连续 2,000 个查询，每个 5 种所需技能，
预算宽度为时薪区间宽度的 5%~50%，覆盖默认权重 / 不同权重 / 不同最低分，
其中四分之一查询技能权重为 0，并含单项权重 100。单线程运行，墙钟时间即 CPU 耗时。

本机（Apple Silicon，Go 1.27）实测：

| 指标 | 实测 | 上限 |
| --- | --- | --- |
| 加载 CPU 耗时 | ~0.16 s | 45 s |
| 2,000 查询累计 CPU 耗时 | ~6.6 s（平均 3.3 ms/查询） | 10 s |
| 峰值内存（向系统申请总量） | ~110 MiB | 512 MiB |
